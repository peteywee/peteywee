name: Deploy GitHub Pages

on:
  push:

jobs:
  build-deploy:
    runs-on: ubuntu-latest

      - name: Checkout repository
        uses: actions/checkout@v3

        uses: ruby/setup-ruby@v1

      - name: Build site with Jekyll
        run: |
          bundle exec jekyll build --destination _site

      - name: Upload artifact for Pages
        uses: actions/upload-pages-artifact@v1
        with:

      - name: Deploy to GitHub Pages
        uses: actions/deploy-pages@v1
What this does:

actions/checkout pulls your Jekyll source.

ruby/setup-ruby installs Ruby so Jekyll can run.

bundle install reads your Gemfile and pulls in Jekyll plus any plugins/themes.

You can absolutely hook into “command not found” events in Bash (and similar shells) to auto-install missing tools. The trick is to define a special Bash function called command_not_found_handle (Zsh has its own hook too) that gets invoked whenever you type a command that isn’t on your $PATH. Inside that handler you can:

Detect which package manager you’re using (e.g. apt, dnf, brew, etc.).

Try to map the missing command name to a package (e.g. via apt-cache search).

Prompt (or auto-approve) an install.

Rerun the command once the install completes.

Here’s a self-contained snippet you can drop into your bootstrap.sh (after you detect and set $PMGR) or directly into your ~/.bashrc:

# --- Auto-install missing commands via command_not_found_handle ---
command_not_found_handle() {
  local cmd="$1"; shift
  echo "⚠️  '$cmd' not found. Attempting to install…"

  case "$PMGR" in
    apt)
      sudo apt-get update -qq
      # find a package that exactly matches the command name
      pkg=$(apt-cache --names-only search --quiet "^${cmd}$" \
            | awk '{print $1}' | head -n1 || echo "$cmd")
      if confirm "Install package '${pkg}'?"; then
        sudo apt-get install -y "$pkg"
        # re-invoke the original command with any extra args
        exec "$cmd" "$@"
      fi
      ;;
    dnf)
      if confirm "Install package '${cmd}'?"; then
        sudo dnf install -y "$cmd"
        exec "$cmd" "$@"
      fi
      ;;
    brew)
      if confirm "Install package '${cmd}' with brew?"; then
        brew install "$cmd"
        exec "$cmd" "$@"
      fi
      ;;
    *)
      echo "🔌 Auto-install not supported for package manager: $PMGR"
      ;;
  esac

  return 127  # standard “command not found” exit
}
How this works
Bash hook: By defining command_not_found_handle, Bash will call it whenever you run an unknown command.

Package lookup: We use apt-cache search (or analogous tools) to try to find the right package name; if nothing matches, we just use the raw command name.

Interactive install: We prompt you—so nothing ever gets installed without your OK. You can remove the confirm wrapper if you want a truly zero-touch install.

Re-execution: After installation, we exec the original command so your shell session is seamless.

Integration
Make sure $PMGR is set (you already do this in your bootstrap script).

Add the snippet after your package-manager detection block.

Ensure the helper function confirm() exists (you already have that in your script).

Re-source your shell or re-run the bootstrap script.

With that in place, any time you typo or miss a dependency, your system will ask to install it on the spot—and then run it immediately once it’s available.

Here’s how you can fold your interactive bootstrap logic into a repeatable, automated deployment pipeline—whether you’re provisioning VMs, baking images, or spinning up containers.

1. Infrastructure‐as‐Code Provisioning
Terraform + Remote-Exec
Use Terraform’s null_resource with a remote-exec provisioner (or the built-in SSH provisioner) to call your bootstrap.sh after the VM comes up:

resource "aws_instance" "app" {
  ami           = var.ami_id
  instance_type = "t3.micro"
  key_name      = var.keypair

  provisioner "remote-exec" {
    inline = [
      # copy the script up
      "chmod +x /tmp/bootstrap.sh",
      "sudo /tmp/bootstrap.sh --batch"
    ]
    connection {
      type        = "ssh"
      host        = self.public_ip
      user        = "ubuntu"
      private_key = file(var.ssh_key_path)
    }
  }
}
This ensures every “apply” both spins up a clean VM and runs your fully-tested bootstrap in batch mode.

2. Image Baking with Packer
If you’d rather bake a “golden image” that already has your bootstrap applied:

{
  "builders": [{
