Docker-Based VenueShift Application Architecture
I'll transform the OCI-based architecture into a fully dockerized production-ready solution. Here's a complete redesign that maintains the same application functionality but replaces OCI components with portable Docker-based alternatives.

Overview of Changes
The original architecture used OCI Compute VM, OCI Autonomous Database, OCI Vault, and OCI Container Registry, with Cloudflare for frontend hosting and connectivity. I'll convert this to a Docker-based solution, while keeping Cloudflare components (Pages and Tunnel) since they're valuable for frontend hosting and secure connectivity.

New Dockerized Architecture
Technology Stack
Category	Old Technology	New Technology
Compute	OCI Compute VM (Ampere A1)	Docker containers orchestrated with Docker Compose
Frontend Hosting	Cloudflare Pages	Cloudflare Pages (unchanged)
Database	OCI Autonomous DB (PostgreSQL Mode)	PostgreSQL container with persistent volume
Authentication	Firebase Authentication	Firebase Authentication (unchanged)
Secrets	OCI Vault	Docker secrets or .env files with Docker Compose
Container Registry	OCI Container Registry (OCIR)	Docker Hub or GitHub Container Registry
Entry Point/CDN	Cloudflare (Pages + Tunnel)	Cloudflare (Pages + Tunnel) (unchanged)
IaC	Terraform (OCI Provider)	Docker Compose files
CI/CD	GitHub Actions	GitHub Actions (modified for Docker)
Process Management	pm2 (on VM)	Docker container orchestration
Reverse Proxy	nginx (on VM)	Nginx container

services:
  # PostgreSQL Database
  postgres:
    image: postgres:15-alpine
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./docker/postgres:/docker-entrypoint-initdb.d
    env_file:
      - .env
    environment:
      - POSTGRES_PASSWORD=${DB_PASSWORD}
      - POSTGRES_USER=${DB_USER}
      - POSTGRES_DB=${DB_NAME}
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "${DB_USER}"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    networks:
      - backend

  # Backend API
  backend:
    build:
      context: .
      dockerfile: Dockerfile.backend
    depends_on:
      postgres:
        condition: service_healthy
    env_file:
      - .env
    environment:
      - NODE_ENV=production
      - DB_HOST=postgres
      - DB_PORT=5432
      - DB_USER=${DB_USER}
      - DB_PASSWORD=${DB_PASSWORD}
      - DB_NAME=${DB_NAME}
      - SESSION_SECRET=${SESSION_SECRET}
    restart: unless-stopped
    networks:
      - backend

  # Nginx reverse proxy
  nginx:
    build:
      context: .
      dockerfile: Dockerfile.nginx
    ports:
      - "80:80"
    depends_on:
      - backend
    restart: unless-stopped
    networks:
      - backend

  # Cloudflared tunnel client
  cloudflared:
    image: cloudflare/cloudflared:latest
    command: tunnel run
    volumes:
      - ./docker/cloudflared:/etc/cloudflared
    restart: unless-stopped
    networks:
      - backend

volumes:
  postgres_data:

          node-version: '18'

        run: cd packages/frontend && npm run build
        env:
          VITE_API_BASE_URL: ${{ secrets.API_URL }}
          VITE_FIREBASE_API_KEY: ${{ secrets.FIREBASE_API_KEY }}
          # Add other environment variables
      - name: Deploy to Cloudflare Pages
        uses: cloudflare/wrangler-action@2.0.0
        with:
          apiToken: ${{ secrets.CF_API_TOKEN }}
          accountId: ${{ secrets.CF_ACCOUNT_ID }}
          command: pages deploy packages/frontend/dist --project-name=venueshift

  deploy-backend:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Log in to container registry
        uses: docker/login-action@v2
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v2
      
      - name: Build and push backend
        uses: docker/build-push-action@v4
        with:
          context: .
          file: ./Dockerfile.backend
          push: true
          tags: ghcr.io/${{ github.repository }}/backend:latest
      
      - name: Build and push nginx
        uses: docker/build-push-action@v4
        with:
          context: .
          file: ./Dockerfile.nginx
          push: true
          tags: ghcr.io/${{ github.repository }}/nginx:latest
          
      - name: Deploy to server
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_KEY }}
          script: |
            cd /opt/venueshift
            docker-compose pull
            docker-compose down
            docker-compose up -d

Security Enhancements for Docker
Secrets Management:
Use .env files for Docker Compose (not committed to Git)
For more sensitive environments, use Docker Swarm secrets or a secrets manager like HashiCorp Vault
Container Security:
Run containers as non-root users
Use minimal base images (Alpine-based when possible)
Implement content trust for Docker images
Regular vulnerability scanning with tools like Trivy
Network Security:
Keep Cloudflare Tunnel for secure ingress
Use Docker networks to isolate services
Expose only necessary ports
Database Security:
Persistent volume for PostgreSQL data
Regular automated backups
Proper user permissions

Step 6: Configure Database Connectivity for Cloud Run
Cloud Run connects to Cloud SQL using the Cloud SQL Auth Proxy, which is automatically handled by the platform. Update your backend database connection code to support this:

typescript
// In your database connection module
import { Pool } from 'pg';

const createPool = async (): Promise<Pool> => {
  const isProduction = process.env.NODE_ENV === 'production';
  
  // For Cloud Run to Cloud SQL connection
  if (isProduction && process.env.DB_HOST?.includes(':')) {
    // Cloud SQL connection format
    const connectionName = process.env.DB_HOST;
    return new Pool({
      user: process.env.DB_USER,
      password: process.env.DB_PASSWORD,
      database: process.env.DB_NAME,
      host: `/cloudsql/${connectionName}`,
    });
  }
  
  // For local development or other environments
  return new Pool({
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
    database: process.env.DB_NAME,
    host: process.env.DB_HOST,
    port: parseInt(process.env.DB_PORT || '5432'),
  });
};

export const pool = await createPool();
