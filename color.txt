# Color Enforcement Logic – System Role & Palette Governance

## Purpose
This document defines how role-based color mapping is structured, updated, and enforced across the ctl_environment system. It exists to create consistency in visual logic, traceability in updates, and clarity for developers or maintainers working in open or production environments.

## What This System Does
- Maps system "roles" (apps, scripts, files, services) to specific color codes.
- Applies those mappings consistently across CLI, UI, logs, and scripts.
- Enforces logic so colors aren’t arbitrary—they reflect purpose and system context.

## Role Logic
Each role has:
- role: a system component or logical entity (e.g. vault, nginx, auth, logs)
- category: function classification (e.g. security, infrastructure, monitoring)
- hierarchy: how it fits in the system logic (parent, child, cousin, alert, feedback)
- color_code: internal ID for consistency across tools (e.g. COLOR_035)
- hex_value: actual display color used in CLI or UI
- install_hook: used to register/update this role when apps are installed

## How Updates Happen
1. When a new app installs (e.g. grafana), a hook script runs.
2. The script evaluates:
   - What category it fits in (via name, tags, config)
   - What hierarchy it belongs to (e.g. is it a service? UI? logger?)
3. A color is selected from an internal palette:
   - Must follow constraints (see below)
   - Must not conflict with existing mappings unless explicitly overridden
4. The new role is added to color_roles.json.

## Constraints (Hard Rules)
- No use of #FFFFFF (white) or #000000 (black) for any role.
- Any color named “blue” must be replaced with #A020F0 (purple) unless it's directly linked to script tools.
- Hierarchies must be preserved:
  - parent cannot be overwritten by child
  - alert colors (e.g. red, yellow) are reserved for logs, errors, security
- Color reassignments are only allowed via uninstall + re-register, not overwrite.

If you're using this system in a fork:
- You can change the palette (color_palette.json) or mappings (color_roles.json)
- But you must maintain enforcement rules unless you also modify color-laws.json

- color-laws.json: defines hard constraints

# colors.source.sh - Runtime loader for color role schema

# Load color role schema
COLOR_ROLE_SCHEMA_PATH="${COLOR_ROLE_SCHEMA_PATH:-$HOME/.color_roles.json}"

  echo "[ERROR] color_roles.json not found at $COLOR_ROLE_SCHEMA_PATH"
  return 1
fi

# Parse JSON using jq (requires jq)
if ! command -v jq &> /dev/null; then
  echo "[ERROR] jq is required but not installed."
  return 1
fi

# Load roles into environment
export COLOR_ROLE_MAP=$(cat "$COLOR_ROLE_SCHEMA_PATH" | jq -c '.')

# Function to get color hex by role
get_color_by_role() {
  local role="$1"
  echo "$COLOR_ROLE_MAP" | jq -r ".[] | select(.role==\\"$role\\") | .hex_value"
}

# Example: export color for PS1 (prompt)
PROMPT_COLOR=$(get_color_by_role prompt)
export PS1="\\[\\e[38;5;$(tput setaf 5)\\]\\u@\\h:\\w\\$ \\[\\e[m\\]"
"""

function generate_colors_source() {

# colors.source.sh - Runtime loader for color role schema

COLOR_ROLE_SCHEMA_PATH="${COLOR_ROLE_SCHEMA_PATH:-$HOME/.color_roles.json}"

if [ ! -f "$COLOR_ROLE_SCHEMA_PATH" ]; then
  echo "[ERROR] color_roles.json not found at $COLOR_ROLE_SCHEMA_PATH"
  return 1
fi

if ! command -v jq &> /dev/null; then
  echo "[ERROR] jq is required but not installed."
  return 1
fi

export COLOR_ROLE_MAP=$(cat "$COLOR_ROLE_SCHEMA_PATH" | jq -c '.')

get_color_by_role() {
  local role="$1"
  echo "$COLOR_ROLE_MAP" | jq -r ".[] | select(.role==\"$role\") | .hex_value"
}

PROMPT_COLOR=$(get_color_by_role prompt)
export PS1="\[\e[38;5;$(tput setaf 5)\]\u@\h:\w\$ \[\e[m\]"
EOF
}

function generate_install_hook() {
    echo "[+] Generating install_hook.sh..."
    cat > "$BASE_DIR/install_hook.sh" <<'EOF'
#!/bin/bash
# install_hook.sh - Auto-register a new app into color_roles.json

ROLE_NAME="$1"
CATEGORY="$2"
HIERARCHY="$3"

if [[ -z "$ROLE_NAME" || -z "$CATEGORY" || -z "$HIERARCHY" ]]; then
  echo "Usage: $0 <role_name> <category> <hierarchy>"
  exit 1
fi

SCHEMA_PATH="${COLOR_ROLE_SCHEMA_PATH:-$HOME/.color_roles.json}"

if [ ! -f "$SCHEMA_PATH" ]; then
  echo "color_roles.json not found at $SCHEMA_PATH"
  exit 1
fi

HEX_COLOR=$(printf "#%06x" $((RANDOM*RANDOM % 0xEEEEEE + 0x111111)))
COLOR_CODE="COLOR_$(od -vAn -N2 -tu4 < /dev/urandom | tr -d ' ')"

jq ". + [{\"role\": \"$ROLE_NAME\", \"category\": \"$CATEGORY\", \"color_code\": \"$COLOR_CODE\", \"hex_value\": \"$HEX_COLOR\", \"hierarchy\": \"$HIERARCHY\", \"source_type\": \"dynamic\", \"app_linked\": \"$ROLE_NAME\", \"install_hook\": \"hook_${ROLE_NAME}_installed\"}]" "$SCHEMA_PATH" > "${SCHEMA_PATH}.tmp" && mv "${SCHEMA_PATH}.tmp" "$SCHEMA_PATH"

echo "Role $ROLE_NAME registered successfully."
EOF
